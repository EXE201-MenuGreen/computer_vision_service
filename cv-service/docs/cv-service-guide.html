CV Service - Hướng Dẫn Tích Hợp

Tài liệu hoạt động: luồng bất đồng bộ Celery + Redis, xác thực API_SECRET_KEY và phân tích ảnh bằng Gemini.

Tổng quan về cách hoạt động

CV Service nhận ảnh món ăn/nguyên liệu từ C# Backend, đẩy vào hàng đợi bất đồng bộ Celery, và sử dụng mô hình trí tuệ nhân tạo ngoài (như Google Gemini 2.5 Flash) để phân tích hình ảnh trả về thông tin dinh dưỡng, danh sách nguyên liệu và gợi ý các món ăn Việt Nam dưới dạng dữ liệu cấu trúc JSON chuẩn hóa.

  • Xử lý bất đồng bộ (Celery + Redis): Toàn bộ quá trình gọi AI ngoài mất từ 3-15 giây tùy kích thước ảnh và tốc độ API. Để không gây treo request của C# backend, request phân tích sẽ trả về job_id ngay lập tức. C# backend sẽ định kỳ poll trạng thái để lấy kết quả.
  • Xác thực Service-to-Service: Kết nối giữa C# Backend và Python CV Service được bảo vệ bằng cơ chế Bearer Token sử dụng một khóa bí mật dùng chung (API_SECRET_KEY).

Luồng tích hợp hệ thống

1) Client gửi ảnh

  • Client (Mobile/Web) gửi ảnh lên C# Backend (MenuGreen.API).
  • C# Backend xác thực thông tin tài khoản và kiểm tra quyền hạn người dùng.

2) Khởi tạo Job phân tích

  • C# Backend gọi API POST /api/v1/cv/analyze gửi kèm ảnh và header Authorization: Bearer <API_SECRET_KEY>.
  • Python CV Service nhận ảnh, sinh job_id và đẩy tác vụ chạy ngầm vào hàng đợi Celery qua Redis, trả về job_id ngay cho C# Backend.

3) Polling lấy kết quả

  • C# Backend thực hiện lặp (loop) định kỳ mỗi 2 giây gọi API GET /api/v1/cv/jobs/{job_id}.
  • Khi Celery worker gọi Gemini API thành công và ghi kết quả vào Redis, API sẽ trả về trạng thái "status": "done" kèm kết quả JSON.

4) Xử lý logic & Trả phản hồi

  • C# Backend lấy danh sách nguyên liệu sử dụng từ kết quả phân tích để so khớp với danh sách dị ứng của người dùng (Allergens matching).
  • Lưu lịch sử bữa ăn vào Database SQL Server và trả kết quả đã cá nhân hóa về cho Client.
Luồng món ăn đã hoàn chỉnh: dùng POST /api/v1/cv/analyze-meal (hoặc /analyze-meal-sync) và poll GET /api/v1/cv/meal-jobs/{job_id}. Kết quả trả tên món, nguyên liệu suy luận, gram, calories/macros từng nguyên liệu và tổng. Dinh dưỡng được tính qua NutritionService; số liệu vẫn chỉ là ước tính, đặc biệt với dầu, sốt, đường và ảnh không có vật tham chiếu khẩu phần.

Chi tiết API Endpoints

1. POST /api/v1/cv/analyze Tạo Job (Async)

  • Mô tả: Tiếp nhận ảnh, validate định dạng & dung lượng, đẩy vào hàng đợi Celery.
  • Headers: Authorization: Bearer <API_SECRET_KEY>
  • Body (Multipart form-data): image (File ảnh JPEG/PNG/WebP)
  • Response (200 OK): 
    {
  "job_id": "56aadc60-478b-4584-9959-699140a042ba",
  "status": "queued",
  "message": "Analysis queued. Poll /cv/jobs/{job_id} for result."
}

  • Headers: Authorization: Bearer <API_SECRET_KEY>

Ví dụ request phía lập trình viên

1. cURL (Gửi phân tích ảnh)

curl -X POST "http://localhost:8000/api/v1/cv/analyze" \
  -H "Authorization: Bearer 4e9cd42d7b29cc07920ef88f34bc63c4d0fa36a2e19c1e03bd35b9f8bf9fb87e" \
  -F "image=@/path/to/image.jpg"

2. C# (Sử dụng HttpClient trong Services)

// 1. Gửi ảnh và lấy JobID
var request = new HttpRequestMessage(HttpMethod.Post, "/api/v1/cv/analyze");
request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", _apiSecretKey);
var content = new MultipartFormDataContent();
content.Add(new StreamContent(imageStream), "image", "food.jpg");
request.Content = content;

var response = await _httpClient.SendAsync(request);
var jobInfo = await response.Content.ReadFromJsonAsync<CvJobResponse>();
var jobId = jobInfo.JobId;

// 2. Vòng lặp polling kết quả
while(true) {
    await Task.Delay(2000);
    var pollReq = new HttpRequestMessage(HttpMethod.Get, $"/api/v1/cv/jobs/{jobId}");
    pollReq.Headers.Authorization = new AuthenticationHeaderValue("Bearer", _apiSecretKey);
    var pollResp = await _httpClient.SendAsync(pollReq);
    var status = await pollResp.Content.ReadFromJsonAsync<CvJobStatusResponse>();
    if(status.Status == "done") {
        return status.Result; // Hoàn thành phân tích!
    }
}

Một số mã lỗi hay gặp

  • 401 Unauthorized: Mã `API_SECRET_KEY` gửi lên trong Header `Authorization` không trùng khớp hoặc bị thiếu.
  • 422 Unprocessable Entity: Gửi thiếu trường `image` hoặc file gửi lên không nằm trong danh sách định dạng ảnh cho phép (JPEG, PNG, WebP).
  • InferenceClientError (Trong kết quả status: failed): Xảy ra khi CV Service không thể liên kết được với AI ngoài (ví dụ: Google Gemini API key bị sai, hết hạn mức sử dụng hoặc lỗi kết nối).

Các Best Practices khuyên dùng

  • Giữ cổng 8000 đóng phía ngoài mạng (Private Docker Network): Chỉ expose cổng 8000 khi cần debug. Lúc đưa lên staging/production, nên ẩn cổng 8000 của CV service và chỉ cho phép C# Backend kết nối thông qua Docker network nội bộ để tăng cường bảo mật.
  • Sử dụng khóa bí mật mạnh: Hãy luôn tạo mã khóa ngẫu nhiên dài từ 64 ký tự hex ở production để chống lại các cuộc tấn công đoán mã.
